# B 题（优化决策类）方法选择指南

> **适用范围**：全国大学生数学建模竞赛 B 题（优化决策类）。
>
> **核心原则**：先精确后启发，先简单后复杂，能解析不数值，能 LP 不 NLP。

---

## 一、B 题优化方法优先级表

### P0：首选方法（默认先考虑）

| 方法 | 适用场景 | 求解器 | 论文优势 |
|------|---------|--------|---------|
| **解析解** | 问题结构简单、可以直接推导最优解 | 无（手算） | 最扎实，评委最喜欢 |
| **贪心算法** | 有明显贪心结构（如每次选最优局部解） | 无（手写） | 简单易懂，可作为 baseline |
| **规则法** | 题目有明确的业务规则或启发式规则 | 无（手写） | 贴合实际，可解释性强 |
| **线性规划（LP）** | 目标和约束都是线性的，决策变量连续 | GLPK, CBC, Gurobi | 标准方法，结果可靠 |

### P1：次选方法（P0 明显不足时考虑）

| 方法 | 适用场景 | 求解器 | 升级理由 |
|------|---------|--------|---------|
| **整数规划（MILP）** | 有整数决策变量（如 0-1 选择、整数数量） | CBC, Gurobi, CPLEX | LP 无法处理整数约束 |
| **非线性规划（NLP）** | 目标或约束有非线性（如 x²、log(x)、乘积） | IPOPT, SCIP, Baron | LP/MILP 无法表达非线性关系 |
| **动态规划** | 有最优子结构、无后效性、阶段决策明确 | 手写（递推） | 问题天然分阶段，DP 比 LP 更高效 |

### P2：进阶方法（P1 仍不足且有明确证据时考虑）

| 方法 | 适用场景 | 求解器 | 升级理由 |
|------|---------|--------|---------|
| **多目标规划（MOO）** | 有多个冲突目标（如成本 vs 质量） | pyomo（加权法/ε-约束法） | 单目标无法表达权衡关系 |
| **混合整数非线性规划（MINLP）** | 同时有整数变量和非线性约束 | SCIP, Baron, Couenne | MILP 无法处理非线性 |
| **随机规划** | 有不确定性参数，需要考虑风险 | pyomo（场景法） | 确定性规划无法处理风险 |

### P3：谨慎使用（必须有充分论证，否则不建议）

| 方法 | 高风险原因 | 正确使用条件 |
|------|-----------|-------------|
| **遗传算法（GA）** | 容易"近似"掩盖精确解的存在、参数调优黑箱 | 必须先证明精确求解不可行（NP-hard 或规模 >10⁴ 变量） |
| **模拟退火（SA）** | 收敛慢、结果不稳定、可解释性差 | 必须有 baseline 对比，证明 SA 比贪心/局部搜索显著更好 |
| **粒子群（PSO）** | 参数敏感、容易陷入局部最优、理论支撑弱 | 必须有收敛性分析，不能只说"效果好" |
| **强化学习（RL）** | 静态优化用 RL 是典型炫技、训练不稳定 | 仅用于动态决策、序列决策、环境可交互的场景 |

## 二、精确求解 vs 启发式选择标准

### 什么时候用精确求解（pyomo）

| 条件 | 说明 |
|------|------|
| 决策变量 < 10⁴ | 小规模问题，精确求解通常可行 |
| 目标和约束是线性或凸的 | LP/MILP/凸 NLP 有成熟求解器 |
| 需要全局最优解 | 精确求解能证明最优性 |
| 需要灵敏度分析 | 精确求解的对偶变量、影子价格有明确意义 |
| 论文需要扎实的理论支撑 | 数学规划模型 + 求解器 = 标准做法 |

### 什么时候可以考虑启发式

| 条件 | 说明 |
|------|------|
| 决策变量 > 10⁴ 且组合爆炸 | 大规模组合优化，精确求解超时 |
| 目标函数非凸/不可导/黑盒 | 无法用梯度方法，精确求解器不适用 |
| 题目明确要求实时/在线决策 | 计算时间受限，启发式更快 |
| 已经证明精确求解不可行 | 有明确的复杂度分析或超时证据 |

### 启发式使用的硬要求

如果使用启发式算法，必须满足：

1. **先给出数学规划模型**：目标函数 + 约束条件，不能只说"用了遗传算法"
2. **先建立 baseline**：贪心/规则法/局部搜索的结果，作为对比基准
3. **证明精确求解不可行**：复杂度分析（NP-hard）或实际超时证据
4. **参数调优有依据**：不能只说"经过调参"，要给出参数范围和调参方法
5. **结果有稳定性分析**：多次运行的均值、方差、最优值分布
6. **与 baseline 对比**：精度提升多少？计算时间增加多少？是否值得？

## 三、B 题常见炫技信号

### 信号 1：小规模优化用启发式

**表现**：几十个变量、几个约束的问题，直接用遗传算法"近似求解"。

**问题**：本来可以用 LP/MILP 精确求解，用启发式反而显得不扎实。

**正确做法**：先试精确求解，确实不可行（超时、NP-hard）再用启发式。

### 信号 2：静态优化用强化学习

**表现**：一次性的资源分配、路径规划问题，直接上 PPO/DQN。

**问题**：强化学习适用于动态决策、序列决策、环境可交互的场景。静态优化用 RL 是典型炫技。

**正确做法**：静态优化用数学规划（LP/MILP/NLP），RL 只用于真正的动态决策。

### 信号 3：存在解析解却用数值优化

**表现**：公式可以直接推导最优解（如二次函数求导、拉格朗日乘数法），却用黑箱优化器搜索。

**问题**：解析解最扎实，数值优化反而引入误差和不确定性。

**正确做法**：能解析就解析，解析不了再数值。

### 信号 4：启发式不给数学规划模型

**表现**：只说"用了遗传算法求解"，不说优化目标是什么、约束条件是什么。

**问题**：没有数学规划模型，评委不知道你在优化什么，也无法判断方法是否合适。

**正确做法**：先给出完整的数学规划模型（决策变量、目标函数、约束条件），再说明为什么用启发式求解。

### 信号 5：每小问都换一个全新方法体系

**表现**：问题一用 LP，问题二用 GA，问题三用 RL，三个问题完全没有统一建模视角。

**问题**：B 题通常是递进式的，小问之间有联系。每小问换方法体系说明没有深入理解问题。

**正确做法**：尽量保持统一建模视角，小问之间在前面模型基础上扩展。

## 四、B 题 baseline 推荐

### 问题一（基础建模）

- **优先**：解析方法或简单 LP
- **baseline**：贪心算法或规则法
- **目标**：建立问题的基本理解，拿到初步结果

### 问题二（扩展建模）

- **优先**：在问题一基础上扩展为 MILP 或 NLP
- **baseline**：问题一的模型（忽略新增约束/目标）
- **目标**：展示建模的递进性，说明新增因素的影响

### 问题三（复杂优化）

- **优先**：如果是复杂优化，先做贪心 baseline，再考虑 MILP/NLP
- **baseline**：贪心算法或问题二的简化版
- **目标**：证明复杂方法的必要性，展示与简单方法的对比

### 问题四（综合应用）

- **优先**：用前面建立的模型扩展，不要另起炉灶
- **baseline**：前面问题的最优方案
- **目标**：展示模型的通用性和可扩展性

## 五、求解器选择指南

| 问题类型 | 推荐求解器 | 备用求解器 | 注意事项 |
|---------|-----------|-----------|---------|
| LP（线性规划） | GLPK, CBC | Gurobi, CPLEX | GLPK 免费够用，Gurobi 更快但需许可 |
| MILP（整数规划） | CBC, Gurobi | CPLEX, SCIP | CBC 免费，大规模问题可能慢；Gurobi 性能最好 |
| NLP（非线性规划） | IPOPT | SCIP, Baron | IPOPT 免费，适合光滑非线性；非凸问题可能找局部最优 |
| MINLP（混合整数非线性） | SCIP, Baron | Couenne | SCIP 免费，Baron 性能好但需许可 |
| 多目标规划 | pyomo（加权法/ε-约束法） | 无专用求解器 | 通常转化为单目标求解，不要直接说"用了多目标求解器" |

---

## 六、最重要的三句话

1. **能精确就不启发，能简单就不复杂，能解析就不数值。**
2. **使用启发式必须先给数学规划模型、先建 baseline、先证明精确求解不可行。**
3. **B 题小问之间是递进的，尽量保持统一建模视角，不要每小问换方法体系。**
