# Planner：选题、架构与预算

## 选题

题目评分至少覆盖：数据可得性、队伍能力、求解可行性、方法与题目匹配度、可验证性和竞赛 profile 要求。经验覆盖只能提供先验，不能代替题面、附件、时间和能力判断。

拿题后分两次评估：先用初始 fingerprint 做快速筛选；读完题面、附件和数据后更新 fingerprint 并重新评估。最终选择必须记录在项目侧决策包中。

## 经验与文献

- `memory/topic_intelligence.py` 输出经验覆盖、证据质量、风险标签和不确定性；覆盖不足时只用通用契约，不把零散条目当作规范。
- `memory/retrieval.py` 先查 `memory/index.yaml`，再读取命中条目；经验先验必须绑定当前题目证据。
- 文献调研为每篇来源登记方法、适用范围、可迁移点、限制和正文引用位置；文献不足或无法核验时暂停在文献输入门。
- 候选架构形成主模型与备用模型，分别说明数据、约束、解释性、计算成本和验证方法。

## 建模计划

```text
题目解析 → 条件台账/符号表 → 蓝图检索 → 候选架构 → baseline
→ 模型契约 → 求解与验证 → 论文证据映射
```

- 拆解子问题、判定数学本质时按需读 `planner/problem_essence_taxonomy.md`，先区分建模问题与确定性计算，再按本质类型对应能力，不豁免文献与证据门禁。
- 多个候选模型冲突时按需调 `math-model-selector`（模型选择与实现路由已下沉该子 skill，含题目特征、问题规模、用户背景三级裁决），最终选择仍以本题数据、约束和验证证据为准。
- 递进题按依赖顺序求解；上游结果变化时登记下游重算范围。
- baseline 未验证前不得进入复杂模型；baseline 不足时回到模型蓝图和风险探针。
- 每个小问登记目标、状态、约束、算法、参数来源、结果文件、验证方式和图表需求。
- 内容预算来自真实推导、求解、结果和验证证据；不得通过空白、重复图表或无效文字补页。

## 风险登记

开工时登记架构可行性、参数口径、数据质量、结果一致性、引用真实性、AIGC 合规、交付格式和剩余时间。每个阶段结束更新状态，触发高风险条件时暂停并提交决策包。

## 论文节点

- 每个论文小节完成后提交“目标—产物—证据—未决事项—允许修改范围”。
- 写作链为 `academic-writing` 数模学术写作适配层 → 必要时 `humanizer-zh`。
- 写作前冻结符号表、模型契约、结果注册表和图表登记；新符号、数字或图表必须先补来源再写入正文。
- 论文完成后执行数学、代码、正文、图表、引用、摘要、附录、匿名和 AI 工具说明检查。

## 阶段清单

- Planner：题目条件、fingerprint、经验检索、符号表、假设和模型蓝图。
- Executor：baseline、模型契约、求解脚本、运行清单、结果注册和验证。
- Critic：公式推导、符号/单位、模型选择、数字来源、图表引用、引用作用、摘要和适用边界。
- Writer：普通正文表达、论文节点回流、附录映射和成品负向回声扫描。
- Controller：权限模式、暂停点、冻结、冲突裁决和交付门禁。
- Memory：只沉淀已经验证、可复用且不含内部过程的规则。
