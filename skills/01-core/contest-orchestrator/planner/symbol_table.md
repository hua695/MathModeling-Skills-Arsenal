# 符号表（Symbol Table）

> 目的：**统一符号**——同一个符号在题面解析、模型公式、代码变量、论文正文中含义完全一致。
> 论文"符号说明"节（planning.md 论文三件套①）直接从本表导出，不再现场攒。

## 生成时机

```
problem-parser（Problem Graph + Assumptions）→ 【符号表草稿】→ 经验/蓝图检索 → A2-refine（合并新变量）→ 【符号表定稿】
```

- **草稿（A2）**：problem-parser 输出后 15 分钟内建立（拿题当晚），覆盖题目出现的全部关键量。
- **A2-refine（A4 蓝图检索后）**：蓝图/经验引入的新变量先登记进表，合并后才产出正式 `symbol_table.md`——避免"先定稿后引入蓝图变量"导致符号冲突。
- **增量**：建模过程中新增符号 → 先登记进表 → 才能在公式/代码中使用。
- **定稿**：论文写作前冻结（从 A2-refine 产物导出）；LOCK 阶段禁止新增符号（要新增 = 改模型，冻结期不允许）。

## 格式

| 符号 | 含义 | 单位 | 类型 | 首次出现 | 备注 |
|---|---|---|---|---|---|
| $N$ | 总样本数 | - | 参数 | 问题1 | 数据规模 |
| $x_{ij}$ | 第 i 个样本第 j 个特征 | - | 输入 | 问题1 | |
| $\hat{y}_i$ | 第 i 个样本预测值 | - | 输出 | 问题1 | |
| $\beta$ | 感染率 | day⁻¹ | 参数 | 问题2 | SIR 模型 |

- **类型**：决策变量 / 状态变量 / 参数 / 输入 / 输出（沿用 problem-parser 的变量分类，禁止混类）。
- **单位**：必须写；无单位写"-"（不是空着）。
- **符号规范**：同一物理量全队一个符号（禁止"论文里 T、代码里 t、题解里 tau"）；中文论文用 LaTeX 数学符号，代码变量名可映射但注释标明。

## 规则

1. **登记才能用**：公式或代码中出现表外符号 → 先补登记，再继续写。
2. **冲突裁决**：题目给的符号优先沿用题面；题面未定义的按惯例（数学建模教材常用符号）。
3. **对账时机**：论文写作前（符号说明节导出）+ 提交前（Critic 一致性检查：正文符号 ⊆ 符号表）。
4. **与代码一致**：脚本里的变量注释标注对应符号（如 `# beta: 感染率 (day^-1)`）。

## 输出

- `planner/symbol_table.md`（本表，赛中持续维护）
- 论文"符号说明"节：定稿时从表导出（只放论文用到的行，按出现顺序排）
- 提交前 Critic 对照：符号表 vs 正文 vs 代码注释三方一致
