# 文献调研报告模板（五段式 · 可粘贴到论文第2节）

> **使用说明**：此模板由 `planner/literature_survey.py` 根据用户提供的文献元数据、摘要和结构化全文总结生成。文献检索与全文下载由用户完成，指定文献 agent 阅读全文后回传总结；主 Agent 不读取全文。所有 Harness profile 的文献总数硬范围为 6–11 篇，推荐 8–10 篇；中文文献按小问至少各覆盖 1 篇，英文文献不设硬性最低数量但建议覆盖全部小问。数量或字段不足时只输出需求卡和暂停状态，不生成正式综述。解锁后输出四个文件：
> `literature_request.md`、`literature_request.yaml` 和 `literature_agent_prompt.md` 先行生成，包含每个小问的覆盖目标、数量和可直接交给文献 agent 的提示词。
> - `literature_report.md` — 五段式审计报告；正文只提炼与本题相关的方法、缺口和引用作用，不整段复制
> - `references.yaml` — 参考文献清单（写作阶段用）
> - `method_transfer_map.json` — 中文文献方法到各子问题的采用/改造/舍弃登记
> - `citation_map.json` — 章节→引用映射表（写作对照）
> 每条文献同时有稳定 `citation_key`；它必须在参考文献、引用映射、方法迁移表和 `.bib` 中保持一致。

---

## 位置说明

放在国赛论文的 **第2节「问题分析」** 下面，紧接"问题重述"之后：

```
1 问题分析（或问题重述）
2 问题分析
   2.1 文献调研    ← ⭐ 本节内容
   2.2 解题思路 / 模型建立
```

篇幅控制在 0.5～1 页，不要写成长篇综述。

## 模板正文

### 2.1 文献调研

针对本赛题的研究方向，本文对相关学术文献进行了系统检索与梳理。检索覆盖的研究主题包括：[研究大方向]、该类模型（优化/预测/评价）和测量/应用场景相关文献。采用的检索关键词涵盖「[关键词1]」「[关键词2]」等核心术语及其同义词。竞赛题面和附件只作为输入资料登记，不作为正式学术参考文献。

用户根据需求卡检索并下载文献全文，文献 agent 阅读全文后只回传元数据、摘要、方法、数据、适用边界和定位信息。主 Agent 只基于摘要与结构化总结进行题目覆盖分析，不主动联网检索、不直接读取全文。竞赛题面和附件只作为输入资料登记，不作为正式学术参考文献；不能用题面、通知、博客或占位条目替代学术文献。

#### 研究方法分类归纳

**- [方法类别A]**

代表性工作：文献[1](2024)、文献[3](2023)、文献[5](2022)。

这类方法的优势在于能够有效处理大规模组合空间，但在复杂约束条件下的可行性保持仍具挑战。局限性在于：实验数据可能过于理想化，实际场景泛化性待验证。

**- [方法类别B]**

代表性工作：文献[2](2024)、文献[4](2023)。

这类方法的优势在于能捕捉非线性关系和高维模式，但通常需要较大数据量支撑，且可解释性较弱。局限性在于：训练过程稳定性差、超参数敏感是普遍问题。

#### 研究缺口与创新点来源

已有文献对整数规划、非线性约束的关注不足——多数模型在简化假设下运行，未充分处理实际场景中这些约束同时作用时的耦合效应。

部分文献仅研究了单目标或单阶段的简化版本，对于本题多层级、多阶段的递进结构缺乏系统性处理方法。

现有研究方法偏集中于启发式优化类方法，其他可能的技术路线（如互补的数据驱动方法、混合建模策略等）尚未得到充分探索。

#### 与本文建模的关联

本文借鉴了文献[1]的方法思路作为建模的基础框架，同时针对赛题涉及的实际约束条件做了以下修改与改进：

- Q1建模参考了文献[1][3]的思路，将原始方法中的启发式扩展，引入了赛题特有的约束条件，改进了目标函数设计。
- Q2建模参考了文献[2]的动态调度机制，针对时间窗硬性约束设计了新的状态转移规则。
- Q3能耗优化借鉴了文献[4]的代价函数结构，加入了碳排放惩罚项以实现效率与环保的双重优化目标。

具体而言，本文将文献中的通用模型针对本题数据规模和约束特征进行了定制化改造，详见后续各章建模过程。每个子问题须在 `method_transfer_map.json` 中明确记录采用（adopt）、改造（adapt，附 `innovation_delta`）或舍弃（reject，附理由）。

> **引用标记规范**：正文中凡借鉴文献观点、模型、算法、公开参数或测量先例之处，必须说明文献作用，并将引用紧贴对应内容、放在句末标点之前。上角标、方括号或顺序编码服从论文模板；文末参考文献列表按 GB/T 7714 顺序编码制排列，与正文引用顺序严格一致。题面和附件不得作为正式 `.bib` 条目。

## 注意事项

### ✅ 应该做的
- 每处引用都要有实质性讨论（不只是"某某人用了某方法"）
- 每处引用都要明确作用（理论依据/参数来源/测量先例/选择准则/算法实现/适用边界）
- 文献描述要与你的实际建模对应（不要引用了一篇关于 LSTM 的文献却在模型里用了遗传算法）
- 引用标记必须紧贴来源句，并位于句末标点之前

### ❌ 不应该做的
- ❌ 不要写成"A做了XX，B做了XX"的人名流水账
- ❌ 不要只在文末列参考文献目录，正文完全不提
- ❌ 不要引用一篇文献却说"该文献采用了深度学习"（实际用的是传统统计方法）— 评审一眼看出假引用
- ❌ 不要超过 1 页篇幅（这不是文献综述论文）

## 交付门禁检查清单（check_literature_citation.py 会校验）

| 检查项 | 预期结果 |
|--------|----------|
| 正文是否包含 `[1][2]...` 引用标记 | ✅ 至少出现 2 次 |
| 每个标记是否在正文上下文中被"使用" | ✅ 周围有实质性讨论 |
| 是否有孤儿引用（仅在文末列表但正文不调用） | ❌ 不允许 |
| 是否有正文引用但文末无对应条目 | ❌ 不允许 |
| 引用是否说明文献作用 | ✅ 每条至少一种作用 |
| 引用是否位于句末标点之前 | ✅ 全部通过 |
| 文献描述与技术章节是否匹配 | ✅ "启发式"附近应引用启发式类文献 |
