# Critic：论文、模型与合规审查

Critic 只根据当前项目源文件、运行清单、结果注册、PDF 文本层和可核验来源出具问题清单。每条问题必须包含路径/页码、实际证据、影响、最小修改和阻断级别。

## 四类审查

| 子评审 | 核验范围 | 产物 |
|---|---|---|
| Math-Critic | 假设、符号、单位、公式、推导、边界、可辨识性、目标和约束 | `critic_report/*_math.md` |
| Code-Critic | 代码、seed、输入、运行清单、结果和哈希 | `critic_report/*_code.md` |
| Paper-Critic | 结构、正文数字、图表引用、摘要、表达和论文经验适配 | `critic_report/*_paper.md` |
| Compliance-Critic | 引用真实性、匿名、AI 工具说明、附录和交付格式 | `critic_report/*_compliance.md` |

四类报告汇总为 `critic_report/*_summary.md`。任何证据不足的问题标记为待核验，不得当作事实写入论文。

## 数学证明链

```text
假设 → 定义 → 原始关系 → 推导 → 模型 → 算法 → 结果 → 验证
```

逐项检查：

- 每个符号在首次使用处有含义、单位/量纲、取值域和变量类型；
- 每个关键公式有 `original → intermediate/rearranged → final` 依赖链；
- 参数有题面、数据、文献或可复现实验来源；
- 定理条件、边界情况、可行域、目标退化和参数可辨识性得到检查；
- 至少给出适用边界、误差来源或反例分析中的适用项。

## 一致性与可复现

- 正文、公式、表格、图表、附录和摘要的数字均回溯到结果文件或可复算关系。
- 代码、输入、运行清单、结果和图表之间通过路径、来源 ID 和 SHA-256 关联。
- 图表必须有登记、生成脚本、单位、正文引用和解读；视觉检查默认不运行。
- 引用必须真实存在，且正文说明其方法、结论或迁移作用；不能只堆参考文献编号。

## 论文经验检查

调用 `memory/paper_retrieval.py` 获取按章节、题型和竞赛 profile 过滤的 patterns 与 traps。逐条记录命中证据或不适用原因，不能把经验库内容原样写入论文。

重点检查：摘要是否逐问给出结果并有独立总评；模型是否有选型理由；灵敏度是否有题型依据和结论；结果是否含数字、单位和机制解释；附录是否覆盖实际使用的核心材料；正文是否出现内部流程词、元话语或未定义符号。

## 成品阻断

以下任一项未通过，不得进入正式交付：模型或数字无法追溯、关键符号未定义、推导链断裂、引用无法核验、图表来源缺失、附录与正文不一致、匿名失败、AI 工具说明缺失、PDF 文本层含内部交流语言，或交付包与当前源文件漂移。
