# 论文作者证据协议

本协议把技术产出转换为论文作者可以直接使用的读者论证材料。它不是正文目录，也不是页数或字段清单；它只规定写作者在动笔前必须知道的事实关系。

## 1. 证据先形成读者回答

每个小问至少形成一条完整链路：

```text
题目要解决的矛盾
→ 数据与假设的适用范围
→ 为什么采用该模型
→ 题面条件如何进入公式和约束
→ 求解器最终接收什么
→ 结果呈现了什么模式
→ 结果对决策意味着什么
→ 可靠性、局限和可推广方向
```

H5 在 `model_summary_cards.yaml` 的 `reader_evidence` 中登记这条链路。H6 只核验已有证据，不替写作者推断缺失内容。H8 只从已核验字段组织论证，不补造数据、公式、引用用途或模型评价。

## 2. 数据范围与章节落位

在每个小问的模型卡中登记 `data_scope.mode`：

- `shared`：多个小问共用的数据、参数或预处理结果在前文统一说明；本问只说明新增使用方式。
- `independent`：本问数据只服务本问，在本问引入前说明来源、字段和处理。
- `hybrid`：公共数据在前文统一说明，本问专用字段、参数或派生量在本问说明。

`placement_rationale` 必须说明这种落位如何减少重复、保持口径一致并让读者知道当前数据从何而来。不得为了扩大篇幅重复数据字典或预处理过程。

## 3. 假设、推导与评价的可追溯链

每条进入模型的假设都要回答五件事：假设是什么、依据是什么、进入哪个模型组件、不成立会怎样、由什么验证或边界证据支撑。推导弧至少说明一个“从什么到什么”的转译动作及其必要性，帮助写作者把代码和公式还原成可读的数学叙事。

模型评价必须由证据支撑：优点对应可观察的模型行为或验证结果；局限指出来源、影响和适用范围；改进方向逐一对应局限，并写明预期改善对象。不得用“模型合理、效果较好、具有推广价值”等无证据评价替代分析。

## 4. 结果分析的最低读者回答

每张结果解释卡都要说明：读者观察到的模式、比较基准、该模式如何改变或支持方案判断，以及结论成立的边界或证据支持的例外。正文不逐项复述表格数字；先指出模式，再引用关键量化证据，最后解释其现实含义和适用范围。

## 5. 图表只在增加理解时占用版面

H7 在视觉论证计划中先记录读者问题和证据信息单元，再选择 `representation.mode`：

- `figure`：趋势、分布、关系、空间结构、模型结构或算法过程需要视觉编码；必须登记图前引出职责和图后解释职责。
- `table`：少量离散结果适合直接逐项比较；必须登记结构化表格理由。
- `text`：正文、公式或已有表格已经完整回答问题；必须说明不出图的理由。

这一步不设固定总图数，也不允许以“图数达标”为理由出图。图表生成仍按 `SciPilot → ModelViz → SciPilot` 或已登记的流程图/示意图路由执行；排版只负责落实 `layout_mode`，不改变图表语义。

## 6. 论文 agent 的写作顺序

H8A 用上述证据生成作者简报。H8B 每章先形成连续的作者思路：开头要解决的张力、证据出现的自然顺序、证据转为读者理解的解释动作、交给下一章的问题；再写正文。建模问题保持“问题引入与建模思路段—模型建立—模型求解与结果分析”的结构，模型框集中放在模型建立小节末尾。

正文段落遵循“读者疑问—必要证据—解释意义—自然过渡”，不按上游文件顺序拼接。公式、代码和表格只有在帮助读者理解模型、结果或边界时才进入正文。发现推导、结果、验证、图表或引用依据不足时，返回具体 `evidence_gap`，回到责任节点补证据，不用背景扩写、重复结论或泛泛评价填充篇幅。
