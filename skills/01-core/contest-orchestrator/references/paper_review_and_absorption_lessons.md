# 论文审阅与优秀论文吸收规则

本文件将已通过真实论文闭环验证的做法整理为可迁移规则。它服务于项目侧的论文写作、审阅和交付，不是论文正文，也不应把审阅记录、交接内容或样本文本复制进成品。

## 0. 论文编辑路由

论文事实、模型、数字、图表和引用冻结后，按以下顺序执行：

```text
academic-writing/modules/claim-centered-editing
→ academic-writing
→ mathmodel_patch_guard
→ humanizer-zh
→ integrity/delivery gates
```

论证中心编辑只处理普通正文的主张—证据—范围表达。涉及公式、符号、数字、引用、表格、图表、模型逻辑或结果的修改，必须退回对应上游节点重新核验。编辑输出完整修订正文，并仅用 `【需要作者补充证据】` 或 `【需要作者重审主张】` 标记无法由现有材料确认的事项。

## 1. 节点式论文闭环

论文写作采用“可暂停、可核验、可继续”的节点结构，暂停点只放在会改变事实、模型、篇幅或交付风险的地方，不把每次排版微调都变成等待点。

| 节点 | 进入条件 | 必须核验 | 通过后形成的事实 |
|---|---|---|---|
| 结果冻结 | 各小问结果和验证材料已生成 | 结果文件、代码运行证据、题目参数和图表来源一致 | 主结果及其来源冻结 |
| 单问闭环 | 一个 6.x 小节准备定稿 | 输入输出、假设、符号、推导、算法、结果、可靠性证据齐全 | 本问可独立阅读和复核 |
| 摘要定稿 | 正文和结果均稳定 | 每个数字可回溯，方法、结果、检验和总评完整 | 摘要只保留最终事实 |
| 附录冻结 | 正文需要支撑材料 | 代码、长推导和验证模块均真实存在并与正文锚点对应 | 附录覆盖不靠虚构内容 |
| 最终交付 | PDF、源文件和支撑包准备同步 | PDF 文本层、引用、数字、版面日志、成品泄漏和交付新鲜度 | 只交付最终定稿材料 |

每个节点的审阅包至少说明当前目标、输入产物、核验结果、未决事实和下一节点允许的修改范围。子 agent 负责独立发现问题和给出证据，不拥有事实裁决权；主 agent 必须重新读取当前源文件及 PDF 文本层后再决定修改。审阅发现按 `TRUE_CURRENT`、`STALE_REPORT`、`UNVERIFIED` 分类，过期清单和证据不足的猜测不进入修改项。

## 2. 单问建模的最小证据闭环

每个子问题的正文应按以下顺序组织，避免“调用算法后直接给答案”：

```text
题目输入与输出映射
→ 假设和变量定义
→ 原始关系
→ 中间推导
→ 目标函数/状态方程/约束
→ 算法与关键参数
→ 中间结果
→ 主结果
→ 本问校验与向后传递接口
```

每个重要结论都应能建立“主张 → 公式或规则 → 结果文件/表图 → 解释”的链条。由结果计算出的差值、比值、间隔或比较结论也要登记来源或可复算关系，不能只因原始数字存在就视为有来源。正文篇幅来自真实推导、结果和检验；不能用空白、重复叙述、无效图表或固定分页填充。

## 3. 符号与推导防黑箱

- 新符号第一次出现在正文时，附近必须给出含义、单位或量纲、取值域/变量类型；撇号、帽号、粗体、上下标、状态、动作、策略和辅助函数按独立符号处理。
- 总符号表不能替代首用定义。表中仅为统一口径保留、正文未使用的符号可作为兼容警告，但正文实际使用的符号不得依赖读者猜测。
- 公式链至少登记 `original → intermediate/rearranged → final`；每一步说明来源、变形依据和业务/物理含义，避免从代码输出或最终公式直接跳到结论。
- 算法说明应覆盖选择理由、初值或搜索范围、约束处理、终止条件、异常处理和局部最优/过拟合边界。可以使用精确枚举、动态规划或简单基线，但必须解释为什么与题目规模和目标匹配。
- Q1–Q4 的接口变量、单位和质量/成本口径必须一致；一个小问的结果成为下一问输入时，正文要说明传递对象及其边界，不能仅凭图中箭头暗示。

## 4. 成品反元话语与负向回声

论文成品只陈述当前最终状态。应清除指向评审、用户、agent、提示词、交接、修改轮次、调试、失败尝试、被否决内容、旧版本和内部协作的文字。学术导航语可以保留，例如“本文研究”“本节定义”“图 3 展示”“由式（8）可得”，但不能让导航语承载内部工作流信息。

交付前同时扫描：

1. 展开后的 TeX 正文、摘要、图题、表题和附录文字；
2. 编译 PDF 的文本层；
3. 正式交付目录中的文件名、索引和说明。

审阅报告、运行日志、快照和临时目录是工程证据，不是论文内容；它们不能被复制到摘要、正文、图表说明或正式交付包。若需修复普通正文，采用 `PROSE_ONLY`；涉及符号定义时采用 `NOTATION_DEFINITION`；涉及公式、参数、数字或模型逻辑时升级为 `MODEL_CHANGE`，重新求解、验证并取得相应节点批准。

## 5. 优秀论文的吸收边界

优秀论文只提供弱先验。阅读后先提取“可检验的结构规则”，再映射到本题材料；不得直接移植样本文本、数字、结论、公式、图表或与本题无关的参数。建议从以下维度吸收：

- 章节职责：问题分析、假设、符号、建模求解、检验和评价各自承担什么工作；
- 单问节奏：模型动机、推导、算法、结果和即时解释如何形成闭环；
- 信息密度：每段是否包含可核对的变量、方法、数据、公式或结论；
- 图表叙事：图表前说明要检验的主张，图表后解释趋势、边界和决策含义；
- 结论边界：把适用条件、参数化情景、局限和推广方向写清楚，不夸大外推；
- 附录组织：只收录真实运行代码、长推导和验证材料，正文与支撑包可以互相定位。

吸收结果必须经过三次过滤：

```text
样本优点 → 本题可迁移规则 → 当前证据是否支持 → 写入正文或仅保留为项目规则
```

如果某种表达只增加“像优秀论文”的外观，却没有新增证据、解释或可复核性，应删除。结构借鉴不能替代数学审稿，仍需由 Critic 逐式检查假设、单位、推导、数值合理性和结论边界。

## 6. 视觉与人工检查边界

默认不执行自动视觉质检、截图或渲染复核；文本层、结构、公式、数字、引用、图表来源和 PDF 完整性检查照常执行，由用户进行肉眼版面检查。只有用户明确要求视觉检查或显式启用 `--visual-check` 时，才运行视觉入口，并按其失败结果处理。图表证据覆盖检查仍然执行，它验证“图表是否支撑论证”，不等同于视觉美观检查。

## 7. 可复用的审阅输出格式

每条问题必须包含：当前文件路径或 PDF 页码、实际文本/结构证据、对正确性/可复现性/排版的影响、最小修改建议、是否必须修改。若当前证据表明已经满足要求，记录“已核验通过”，不重复报告过期问题。最终由 `check_paper_integrity.py`、摘要/引用/附录门禁、LaTeX 警告检查和交付门禁共同确认，不能用单个关键词扫描替代完整审阅。
