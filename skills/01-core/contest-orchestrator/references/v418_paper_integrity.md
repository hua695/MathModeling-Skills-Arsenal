# v4.18 论文完整性规则

本文件描述 v4.18 稳定版论文完整性规则。稳定版由 `VERSION`、`SKILL.md` 和
`manifest.yaml` 共同声明。

## 节点协作

`COLLAB` 只在 G0–G6 决策包暂停。每个节点提交当前目标、产物路径、SHA-256、验证结果、未决事项和下一节点允许修改范围。子 Agent 负责独立检查，不拥有事实裁决权；主 Agent 必须重新读取当前源文件和 PDF 文本层。

子 Agent 的发现使用三态分类：

- `TRUE_CURRENT`：当前源文件、PDF 或可复现实验均支持；
- `STALE_REPORT`：报告与当前源文件或 PDF 不一致；
- `UNVERIFIED`：证据不足，不进入修改清单。

## 符号完整性

模型契约或 Markdown 符号表中的每个符号必须有含义，并在正文中可追溯。撇号、星号、帽号、波浪号、粗体、上下标、状态、动作、策略和辅助函数均视为独立符号。新项目可使用 `--strict-first-use`，要求符号在正文首次出现前或同一语句中完成定义；已有项目若提供权威符号表，表内定义可作为兼容依据，未直接使用的保留项仅报告警告。定义检查应覆盖 TeX 源文件和编译 PDF 文本层。

## 元话语与负向回声

学术导航语可以保留，例如“本文研究”“本节定义”“图 3 展示”“由式（8）可得”。必须阻断指向评审、用户、Agent、提示词、修改轮次、调试、旧版本和内部讨论的成品文本。

负向回声检查同时覆盖：

1. 当前论文 TeX 源文件；
2. 编译 PDF 的文本层；
3. 正式交付目录的路径和文件名。

快照、临时目录、日志和审阅材料不属于论文内容扫描范围，但不得被复制进正式交付目录。

## 视觉检查默认策略

视觉版面检查是显式选择项，不是每次节点检查的默认步骤。默认不调用视觉质检、截图、渲染复核或视觉合同检查，由用户直接肉眼检查；文本层、结构、公式、数字、引用、图表证据来源和 PDF 完整性检查照常执行。

以下入口默认记录 `SKIPPED_USER_OPT_IN`，不伪装成 `PASS`：

- `audit_project.py` 的自动视觉质检；
- `delivery_gate.py` 的自动版面启发式检查；
- `delivery_all.py` 与 `docx_pipeline.py` 中的视觉质检和视觉合同检查。

用户明确要求“视觉检查/视觉质检/检查第 X 页或某张图”，或命令中加入 `--visual-check` 时，才执行对应自动检查。显式启用后仍须按原门禁处理失败；未启用时报告必须保留跳过状态，不能宣称已完成视觉验收。图表证据覆盖检查仍运行，因为它验证论证支撑关系，不替代肉眼版面判断。

## 修改分级

- `PROSE_ONLY`：公式、数字、引用和表格不得改变；
- `NOTATION_DEFINITION`：允许补充符号定义，但必须保持公式语义和结果不变；
- `MODEL_CHANGE`：必须重新求解、验证并重新取得相应节点批准；
- `DELIVERY_ONLY`：只读检查，不修改源文件。

检查入口：

```text
python scripts/check_paper_integrity.py <paper-root> \
  --symbols <model-contract.yaml> \
  --symbol-table <symbol-table.tex> \
  --pdf <paper.pdf> \
  --delivery-dir <formal-delivery-dir> \
  --out <integrity-report.json>
```
