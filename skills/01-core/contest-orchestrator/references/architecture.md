# 架构与职责

## 五角色闭环

```text
Planner → Executor → Critic → Controller → Memory → Replay
```

- `Planner`：理解题面、选题、确定候选架构和证据需求。
- `Executor`：执行 baseline、建模、求解、图表和结果登记。
- `Critic`：检查失败模式、证明链、一致性、摘要、合规和交付条件。
- `Controller`：按任务范围与权限模式路由，处理冻结和暂停。
- `Memory`：检索已验证经验，保存项目侧 replay 和可复用规则。

## 权限模式

| 模式 | 行为 |
|---|---|
| `AUTO` | 自主执行低风险、可复现和格式性工作；触发冻结或高风险条件时暂停。 |
| `COLLAB` | 连续执行内部计算；架构、核心参数、定稿和交付节点等待确认。 |
| `LOCK` | 冻结模型、数据、结果、来源和提交版本，只提出建议。 |

## 证据流

```text
题面/附件 → 条件台账 → 模型契约 → 代码/运行清单 → 结果注册 → 论文声明
→ 图表/引用映射 → 交付门禁
```

每个环节都必须保留可追溯输入和验证结果；没有证据的结论不能进入下一环节。
