# 主张证据审查参考

本文件是论证内容层的审查参考，在论文 agent 自检或 critic 论证审查时按需读取，不新增机器门禁，也不改变 `templates/paper_claim_coverage.yaml` 的必填结构。机器层的主张覆盖、锚点和哈希校验仍由 `scripts/check_harness_control.py`、`scripts/check_model_evidence.py` 负责，本文件只帮助判断“这条主张在论证上站不站得住”。

## 一、先建主张证据映射

通读全文，提取所有主张性句子，通常出现在小节首尾和结果分析段，逐条登记主张、证据位置、类型和状态，不跳过任何一条。映射可借用 claim_coverage 的条目，在其上用可选字段标注 claim_subtype 与 evidence_status。

| 主张类型 | 含义 | 必须配的证据 |
|---|---|---|
| main 核心结论 | 本文总体判断 | 各子问题结果交叉支撑 |
| comparison 优劣比较 | 一方法优于另一方法 | 同条件对比、多指标、必要时统计检验 |
| mechanism 作用机制 | 因果或内部机理 | 消融、控制变量或因果推断 |
| sensitivity 参数判断 | 参数不敏感或假设合理 | 扰动结果表或灵敏度曲线 |
| boundary 适用边界 | 模型适用范围与局限 | 边界或退化场景测试 |
| innovation 创新点 | 相对已有方法的差异 | 可量化的差异和文献对照 |

## 二、证据状态三级判定

| 状态 | 判定条件 | 处理 |
|---|---|---|
| supported | 有图表或数据直接支撑，强度足以说服评审 | 通过 |
| partial | 有证据但缺一个维度，如单次运行、单一数据集、缺检验 | 补维度后再判定 |
| unsupported | 全文找不到可核验证据，属空泛断言 | 补证据，补不出就删除或弱化该主张 |

比较类主张只有一张结果图、没有同条件基线，最高只能记 partial。收敛性、稳健性主张只有单次运行，记 partial。

## 三、五类常见论证漏洞

| 漏洞 | 表现 | 修复方向 |
|---|---|---|
| 悬空主张 | 结论无数据或图表支撑 | 补指向具体图表编号的引用 |
| 证据超载 | 一张图表支撑过多结论 | 增加证据或删减主张 |
| 逻辑跳跃 | 由 A 直接到 C，缺中间环节 B | 补齐推导或数据转换步骤 |
| 循环论证 | 用结论自身证明结论 | 引入独立外部证据 |
| 稻草人对比 | 基线被刻意弱化 | 换公认强基线重算对比 |

## 四、反方测试

对每条核心结论追问其反面是什么，以及论文里有没有反驳反面结论的证据。答不上来，说明论证不完整，需要补证据，或者把结论弱化到证据能覆盖的范围。弱证据用 suggest、may 一类措辞，强证据才用 show、demonstrate，动词强度必须与证据强度匹配。

## 五、修复顺序

1. 先清除全部 unsupported：能补实验就补，补不出就删主张或降级表述。
2. 再补齐 partial 缺失的维度。
3. 全部条目至少达到 partial，且核心结论 main 必须 supported，论证审查才算通过。
4. 只要存在 unsupported 的核心结论，不进入润色和格式环节，因为表达层修改无法弥补论证缺口。

## 六、与冻结链的关系

主张中出现的每个数字、比较差值、百分比都要能回溯到结果文件或可复算关系。论证审查发现数字无来源时，按证据缺口处理，回到对应节点补结果，不在写作阶段直接改数。
