# 变更影响分级验证

比赛运行期间，项目产物发生变化时先填写 `.contest/change_impact_card.yaml`，再按影响等级执行最小安全复核。该机制减少无关节点重复运行，但不降低模型、数字、来源、图表和正式交付的证据要求。

## 影响等级

| 等级 | 适用变化 | 复核范围 |
|---|---|---|
| `L0` | 正文措辞、普通排版、论文元数据或引用表述变化，模型和数字保护字段未变 | H8 叙事、主张覆盖、成品过程词检查 |
| `L1` | 单张图件或图表登记变化 | H7 图表登记、格式、来源、视觉证据绑定和 SciPilot 视觉检查 |
| `L2` | 单个小问的模型、代码、数据或结果变化 | 该小问 H5 重建视觉证据包，定向 H6，受影响 H7 与 H8 |
| `L3` | 全局数据、符号、跨问接口、全局假设或多小问关系变化 | 从 `earliest_invalid_node` 到 H8 的完整相关链，并刷新视觉证据包 |

## 硬规则

1. 变更卡必须登记项目内相对路径、前后 SHA-256、影响小问、最早失效节点和保护字段。
2. `L2` 只能覆盖一个小问；跨小问变化使用 `L3`。
3. `L0` 不得登记模型、结果、代码或全局接口文件；`L1` 只能登记图件；`L3` 才能登记全局影响。
4. 运行 `scripts/validation_router.py` 生成机器可读复核计划；计划中的节点不得自行扩大或缩小。
5. 项目文件变化不触发 skill 全套测试；skill 源码或检查器源码变化时，将 `skill_code_changed` 设为 `true` 并运行完整技能测试。
6. 任何影响模型、数字、引用用途或图表来源的变化都必须更新下游哈希和审批记录。
7. H9 始终执行 `python scripts/delivery_all.py <项目根> --strict`，任何局部计划都不能替代完整交付门禁。
8. `visual_evidence_packet.yaml` 的信息单元、模型契约哈希或来源文件发生影响时，必须按 L2/L3 重新生成并由当前 H6 实例核验；仅图件变化的 L1 只复核图表与信息单元绑定。

## H8 素材就绪卡

`paper_material_readiness.yaml` 的 `schema_version: "2.0"` 使用 `evidence_matrix` 提供每个小问的紧凑证据状态。矩阵字段必须覆盖问题映射、假设、符号、推导、算法与参数、量化结果、验证、图表或表格、文献使用、结论与边界、敏感性或稳健性；另设 `global.target_length`。

- 有新鲜哈希证据的单元填写 `ready`；
- 缺失或待补单元填写 `missing` 或 `blocked`；
- 明确不适用的敏感性或稳健性分析填写 `not_applicable`，并在素材记录中说明理由；
- `status: PASS` 时所有单元必须为 `ready` 或 `not_applicable`；
- 首次准入不通过时，H8 只输出 `evidence_gap_matrix.yaml`，并回流 H5/H6/H7。

该矩阵是 H8 的入口摘要，底层文件哈希、主张覆盖、模型总结卡、结果解释卡和 H6 核验仍由原有门禁独立检查。
