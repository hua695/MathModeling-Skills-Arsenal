# 建模求解章节结构协议

## 目标

每个小问都要让读者清楚看到三件事：本问要解决什么、模型如何从题面条件推导出来、最终交给求解器的对象是什么。章节结构服务于论证，不把任务卡字段或质量门禁改写成正文目录。

## 全局符号说明

全文只设置一个“符号说明”章节，集中登记跨小问复用的符号、单位、上下标和统一约定。局部符号不另设重复符号表；首次进入正文时，在句中给出含义、单位或量纲、取值域和变量类型。符号表、正文首用定义、公式和代码接口必须保持同一口径。

## 每个问题的默认结构

问题标题之后先写一段不编号的“问题引入与建模思路”段落。该段需要交代本问的任务、已知条件或数据、关键困难、输出目标，以及与前后小问的关系；复杂问题可在文字引入后放置流程图，再用文字承接图示含义。

每个建模问题默认只设置以下两个编号小节：

1. `模型建立`
2. `模型求解与结果分析`

“决策变量”“目标函数”“约束条件”“推导”“算法”“结果分析”等是小节内的无编号加粗引导词，不单独生成编号标题。独立的灵敏度或稳健性分析只有在拥有独立扰动数据、评价指标或稳定性证据时才设置为可选小节；没有独立证据时并入结果分析。

### 模型建立

按读者需要组织假设、局部符号、几何或机理关系、必要推导、目标和约束。推导必须连接题面条件、前置公式和最终计算对象。推导完成后，在本小节末尾设置一个醒目的“最终求解模型”框，集中给出唯一的可计算模型。

模型框至少包含：

- 决策变量及其取值域；
- 参数和已知输入；
- 目标或状态演化关系；
- 约束、边界条件或概率假设；
- 与推导公式及代码接口的对应关系。

优化模型使用 `min/max` 与 `s.t.` 形式；预测模型给出特征、预测函数和训练/预测接口；常微分方程给出状态方程、初值、边界和时间区间；仿真或统计模型给出随机机制、估计对象和输出指标。模型类型不同，表达形状可以不同，但都必须形成一个唯一、可复现的最终求解对象。

### 模型求解与结果分析

说明求解算法、初始化、参数依据、边界、终止条件、异常处理和实现环境，然后呈现本问主要结果。结果后紧接解释其对本问目标的回答、与基准或约束的关系、可靠性证据和适用范围。图表先有文字引导，图表后必须有解释，不把图表登记字段直接写成正文。

## 三方绑定

- H5 解题 agent 依据模型契约和推导登记生成 `model_summary_cards.yaml`，每个小问一张卡，并绑定最终模型表达式、求解接口、来源公式和模型契约哈希。
- H6 验证 agent 独立核对模型卡与公式、符号、单位、代码接口、结果和边界；状态未达到 `verified` 时禁止进入 H8 正文写作。
- H8 论文 agent 读取已核验模型卡，把模型框放在“模型建立”小节末尾，把求解算法和结果分析放在下一小节；不得自行补造模型、数字或符号。

## 写作保护

作者简报、章节卡、模型卡和检查结果只作为内部导航。正文只保留问题引入、推导、最终模型、求解、结果解释和结论；不得出现任务流程、agent、检查项、内部交流或版本信息。
