# H8 写作者优先协议

## 核心定位

论文 agent 的首要任务是让读者理解并接受一条证据支持的论证。作者简报、章节卡和连续性包是写作导航，不是正文目录，也不是逐项抄录的合规清单。

## 全文主线与章节角色

以 `paper_narrative.global.paper_spine` 作为全文章节主线的唯一结构依据，并在作者简报、章节卡和连续性包中保持完全一致。`core` 章节承载建模与求解，是论文的论证中心；`support` 章节是支撑章节，负责问题铺垫、条件说明、结果汇总或结论收束，只服务于核心章节，不另起一条独立论证线。

摘要不作为 H8B 的先行写作任务。H8A 先生成并批准 `abstract_argument_card.yaml`，固定摘要的读者契约、统一建模主线、逐问方法—结果—意义、验证结论、总评和关键词；H8B 每张章节卡必须提供 `abstract_contribution`，H8C 在正文与附录定稿后据此最后写摘要。在 `chapter_parallel` 中，`writing_order` 与最终 `paper_spine`/`chapter_order` 分离：先写依赖满足的建模与求解章节，再写验证、评价、结论、问题分析、前置章节和附录；摘要仅在正式 H8 最后完成。

每章写作前先读取当前章节的 `chapter_role`、`reads_from`、`feeds_to`、`new_claims_allowed` 和 `handoff_question`。在 `chapter_parallel` 中，正文阶段不以实际图件为前提：章节批准后才生成自包含图表提示词；若 `visuals_required: false`，明确记录且不生成提示词。正文必须回答当前 `reader_question`，承接 `reads_from` 指向的已完成论证，并以冻结证据支持的结果推进 `feeds_to` 指向的后续章节。`support` 章节的 `new_claims_allowed` 为空；结论只综合已冻结主张，不新增模型、数字、引用用途或图表解释。正式整合时才从已批准的 `visual_argument_plan.yaml` 与已选 `figure_registry.yaml` 核对图件。缺少图件不阻塞下一章；证据缺口仍返回 `evidence_gap`，不得自行添加计划外图表。

章节之间必须形成自然的“前一章回答了什么—本章因此解决什么—下一章还要回答什么”的读者路径。章节卡字段、agent、节点和检查器属于内部导航，不能在论文中出现。

## 写作顺序

1. 先定位当前章节在 `paper_spine` 中的角色、前置输入、后续承接和允许新增的主张。
2. 先用一句话回答当前章节的读者问题，确认回答只落在冻结证据支持的范围内。
3. 写出本章的解释路径：读者为什么需要这一段、当前证据回答了什么、这一回答如何推进全文主张。
4. 按“问题张力—方法选择—必要推导或过程—结果证据—结果意义—适用边界或自然过渡”组织连续段落；不按输入字段顺序拼接段落。这是论证检查，不是固定段落模板或长度规定。
5. 完成完整叙事后再做符号、数字、引用、图表和范围检查。检查结果留在节点记录，不写入正文。

## 段落写法

每段承担一个清楚的沟通任务，可以从结果、比较、推导或读者问题切入，按内容组织解释与证据。段落长短和句式节奏随论证变化，不规定统一的首句、中段与收尾模板。技术细节只有在帮助读者理解模型选择、推导、结果或边界时才进入正文。

正文一级标题使用中文序号；“模型假设”和“符号说明”分设为两个全局一级章节，符号不在每个小问重复设置独立章节。模型章节采用“问题引入与建模思路段—模型建立—模型求解与结果分析”的结构。模型建立小节内部自然组织局部推导、目标/状态关系和约束/边界，并在末尾呈现已核验的最终求解模型框；模型求解与结果分析小节说明算法、主要结果、结果意义、可靠性和适用边界。章节可以合并自然段，但不能把导航标签直接写成清单式正文。

## 全文连续性

每次写作都读取 `paper_continuity_context.yaml` 和其中绑定的 `paper_spine`。使用已完成章节的收束和术语口径承接当前章节，并在本章结尾回应 `handoff_question` 与 `next_section_question` 所需的过渡。连续性包只提供压缩后的读者路径，不替代当前章节卡和冻结证据。若当前章节无法承接前置章节或无法为后续章节提供所需回答，暂停写作并返回结构性 `evidence_gap`，不得用独立背景段落掩盖断点。用户批准的章节不会因图件返修而失效；返修只由新的 `revision_id` 提示词处理，不阻塞后续章节。

## 输出边界

正文只输出面向读者的最终论证、推导、证据、结果和结论。不得输出作者简报、章节卡、连续性包、检查项、任务流程或内部交流内容。素材不足时返回 `evidence_gap`，不以扩展背景、重复结论或泛化评价制造篇幅。
