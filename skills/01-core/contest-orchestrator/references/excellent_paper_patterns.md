## 2. 可迁移的建模章节顺序

每个子问题在“模型建立与求解”章内形成一个闭环：

```text
题目条件与输出映射
→ 难点和候选路线比较
→ 假设、机理与变量定义
→ 中间关系和推导链
→ 目标函数/状态方程/指标体系及约束
→ 算法、初值、范围、终止和异常处理
→ 中间结果与主结果
→ 子问题即时校验和传递接口
```

不要把所有问题的数值结果集中到检验章；每一问求解完成后立即落地本问的结果、单位、来源和图表。检验章只写事后扰动、残差、交叉验证和鲁棒性。

## 3. 题型对应的证据重点

| 题型 | 主证据 | 常见独立核验 |
|---|---|---|
| 机理/反演 | 物理映射、公式推导、参数可辨识性 | 直接/解析路线与数值拟合路线 |
| 优化/规划 | 决策变量、目标项含义、逐条约束、可行性 | 多起点/备用算法/上下界或小规模算例 |
| 预测/统计 | 数据预处理、基线、数据划分、超参数、指标 | 残差、交叉验证、外推边界和敏感性 |
| 评价/决策 | 指标针对性、正逆向、权重来源、排序规则 | 权重扰动、排序稳定性和方案对照 |
| 动力学/仿真 | 状态/守恒方程、初值边界、步长与求解器 | 步长收敛、守恒残差和场景复算 |
| 混合题 | 子模型类型、接口变量、单位和组合关系 | 接口文件、联合结果与分解结果对照 |

“两条独立路线”只对确有反演或高风险非线性求解的子问题强制；其他题型至少提供一个可解释的基线或对照，不把同一段代码换名当作独立验证。

## 4. 质量反模式

- 只出现“采用某算法”“结果良好”等词，却没有初值、搜索范围、终止条件或结果来源；
- 公式直接跳到最终表达式，没有中间关系、近似条件和单位说明；
- 主模型拟合图、流程图和主结果全部挪到模型检验章；
- 把文件哈希、编译日志、交付索引写成正文模型论证；
- 机器学习堆叠模型没有说明 out-of-fold 预测，或用训练集指标替代独立验证；
- 只报告准确率/单点最优值，不给残差、置信区间、扰动或约束可行性；
- 参考文献只堆在文末，正文没有说明其是理论依据、参数来源、方法先例还是对比边界；
- 将 OCR 乱码、示例数字、AI 工具记录或题面说明书当作正式参考文献。

## 5. 对执行器的要求

生成 `model_contract.yaml` 时，增强模式必须为每个子问题登记：

- `problem_mapping`：输入、输出和题目条件如何进入模型；
- `route_comparison`：候选方案、选用方案及舍弃理由；
- `algorithm_card`：算法选择、初值/范围、约束处理、终止条件和局部最优/过拟合处理；
- `intermediate_results`：粗估计、迭代轨迹、参数表或中间量；
- `result_source`：结果文件、求解器输出、数据表或可复现推导来源；
- `reliability`：至少两类事后可靠性证据。

证据卡不能替代数学审稿。结构检查通过后，仍需由 Critic 逐式核对物理意义、数值合理性和结论边界。
