# Executor：求解、结果和论文素材

## 1. 语言与环境

按子问题选择 Python 或 MATLAB；一个子问题内部保持语言一致，语言和环境写入脚本头部，决定写入项目计划，附录按题号分文件。选择依据是题目性质、数据规模、工具箱、计算资源和可复现性。

| 语言 | 适用方向 |
|---|---|
| Python | 数据科学、机器学习、图论、大规模并行、符号计算 |
| MATLAB | 数值计算、ODE、优化、信号处理和现有工具箱任务 |

## 2. baseline

先运行最简基线，验证问题可解、输入可用、输出指标可计算。基线达到项目目标或数据不足以支持复杂升级时停止扩展；否则依据模型 profile、风险探针和证据计划选择改进路线。基线不承担论文排版和结果展示任务。

## 3. 数学建模

按“题目条件 → 抽象对象 → 变量与参数 → 关系 → 数学问题 → 求解方法 → 计算 → 论文写入”的顺序产出模型。写作阶段只写入已验证的数学框架，不临时补造公式。

建模产出至少包括：

- 决策变量、参数、中间量三类符号及单位；
- 目标函数、约束、现实来源和可行域说明；
- 模型类别、规模量级和求解框架；
- 初始化、边界、终止条件、收敛或间隙标准；
- 复杂度、可行性、收敛性或其他可靠性依据；
- 模型—代码—数据—结果的映射。

数学蓝图按题型指纹检索：高置信度命中时注入 required 骨架，低置信度时只作参考或自建骨架。蓝图提供保底结构，不限制符合契约的模型路线。论文评审使用 `scripts/check_math_contract.py` 检查公式编号、符号闭环和推导链。

## 4. 求解与结果

- 多 seed 或多场景实验记录 seed、参数、环境和选择依据。
- 结果即时写入 JSON/CSV 或项目规定的结构化结果文件。
- 结果只由代码、推导或登记的数据源生成，不使用 stdout 或临时手工结果。
- checkpoint 用于断点续算；关键结果写入 result registry，并绑定代码、输入、结果和图表哈希。
- 每条结果标注 `[已验证]`、`[仅数值]` 或 `[存疑]`；存疑结果不得进入论文结论。

## 5. 代码与可复现

- 题目常量、边界、分组数和 seed 集中配置，避免重复硬编码。
- 跨题复用逻辑抽为公共函数，保持输入、输出和单位明确。
- README 登记依赖、版本、执行顺序、结果位置和复现实验命令。
- 关键变量注释与 symbol table 对齐；数据清洗、删减和中心化规则同时写入代码说明和模型假设。
- 灵敏度、扰动、消融和重复实验按项目计划执行，不使用未经说明的统一比例或次数。

## 6. 可靠性实验

默认实验矩阵为 `baseline → improved model → ablation → sensitivity`，但由题型 profile 和时间预算裁剪。每个被扰动参数记录基准值、范围、输出变化和敏感排序；若题目不存在可识别失效边界，不得虚构临界值。

## 7. 图表

数据结果图使用 `ModelViz → scipilot-figure-skill`；问题分析流程图和技术路线图使用 `tech-route-maker`；原理、机制、受力、几何和公式示意图使用 `tikz-scientific-figures`；Draw.io 仅在用户明确要求时使用。每张图登记真实 generator、输入源、图表角色、QA 状态和可编辑/矢量源。

画图默认进行视觉检查，确认美观、整洁、可读、层级清楚、标注完整；非画图默认不进行视觉检查，除非用户明确要求或显式提供 `--visual-check`。图表门禁仍必须检查数据同源、题注编号、坐标单位、符号一致性和正文解释。

## 8. 论文素材交接

求解阶段同步维护 `paper_outline.md`、符号表、模型契约、结果 registry、敏感性结果、图表 registry 和附录清单。每个子问题完成后提供模型、推导、算法、参数、中间结果、主结果、可靠性和适用边界，供论文写作链使用。
