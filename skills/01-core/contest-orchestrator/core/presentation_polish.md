# 论文表达与版面检查

本文件用于论文写作后的程序化检查和人工定稿。官方模板优先；图表默认执行渲染复核和视觉检查，论文、建模、求解、文献、评审及文档流程默认不执行视觉检查。

## 必查项

1. 错别字、乱码、残留占位符和未定义符号。
2. PDF 文本层不含 LaTeX 源码残留、内部流程词、评审/用户/agent/提示词/交接语言。
3. 公式上下标、分式和编号正确；正文引用的图、表、公式和附录均真实存在。
4. 表格为三线表，无竖线和无关内横线；图表有编号、题注、单位、来源和正文解读。
5. 结果段落包含可追溯数字、比较关系和适用边界，不以孤立参数替代解释。
6. 摘要按项目 profile 检查字数、分段、逐问结论和独立总评；关键词按模板检查数量、位置和格式。
7. 论文不出现赛题抬头、参赛队、参赛编号、身份信息或投稿元数据。
8. 附录只包含真实触发且能支撑正文的内容；程序题提供核心代码，随机算法登记 seed，完整源码放支撑材料。

## 图表路由

- 数据结果图先由 `scipilot-figure-skill` 完成数据剖析和图表决策卡，再由 `ModelViz` 完成模板适配、执行和 SVG/PNG 导出，最后回到 `scipilot-figure-skill` 做科研规范质检。
- 问题分析流程图、技术路线图调用 `tech-route-maker`，保留 `tech-route.json` 和 SVG/PNG，并登记 `generator=tech-route-maker`。
- 原理、机制、受力和几何示意图调用 `tikz-scientific-figures`，保留 `.tex` 和 SVG/PNG，并登记 `generator=tikz-scientific-figures`。
- Draw.io 仅在用户明确要求可拖拽编辑时使用。
- 不使用饼图、双 Y 轴、彩虹色图、无单位坐标轴或把分类点连成无意义折线；图型必须服务于论证目标。

## 表达规则

- 使用准确、克制、信息密度高的学术表达；每段至少提供对象、方法、证据或结论之一。
- 用具体数值、公式编号、引用或适用边界支撑判断，避免宣传性评价和空泛总结。
- `academic-writing` 只修改允许的普通正文表达；数字、公式、引用、术语、表格和模型逻辑修改后必须重新核验。
- `humanizer-zh` 只用于二次自然化，不得引入元话语、口语化内部交流或未经验证的新事实。

## 视觉检查入口

文本层和结构检查始终执行。图表默认运行渲染、截图或自动视觉质检；非图表流程只有用户明确要求或命令显式提供 `--visual-check` 时才启用视觉检查。视觉检查结果不能替代公式、数字、引用和来源门禁。
