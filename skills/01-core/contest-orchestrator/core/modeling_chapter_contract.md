# 模型建立与求解章节契约

本契约适用于不同竞赛和题型；具体页数、章节编号和术语由竞赛 profile 覆盖。

通用推导、假设、算法、可靠性与模型—代码—图表闭环见
[`universal_modeling_contract.md`](universal_modeling_contract.md)。本文件负责章节边界和体量，不能替代通用证据链。

## 1. 章节职责

第六章（或 profile 指定的模型章节）是论文的建模主线，应承载模型思路、备选方案、公式、约束、算法和该子问题的主要结果。第七章只做事后检验，不重新讲述模型选型。

## 2. 体量规则

默认以正文主体页数（不含摘要、参考文献和附录）为分母计算模型章节占比（注意：此处分母仅用于章节占比，与国赛页数规则中"正文最多 30 页"的正文定义不同——后者含正文主体、AI 工具使用声明和参考文献）；模型章节目标占比 45%–55%；低于 42% 时触发补充任务。补充只能增加可验证的建模逻辑，禁止用空白页、强制分页或重复公式填充。

## 3. 子问题固定结构

全文只设置一个全局“符号说明”章节。跨小问复用的符号、单位、上下标和统一约定集中登记；局部符号在正文首次出现处给出含义、单位或量纲、取值域和变量类型，不在每个小问重复设置符号表。

每个 `6.x` 问题标题之后先写一段不编号的“问题引入与建模思路”，交代本问任务、已知条件、关键困难、输出目标及其与前后小问的关系。随后默认只设置两个编号小节：

1. `模型建立`：承载假设、局部符号、必要推导、目标/状态关系、约束/边界，并在小节末尾给出唯一的“最终求解模型”框；
2. `模型求解与结果分析`：承载算法、参数依据、初始化、终止条件、异常处理、主要结果、结果解释和适用范围。

“决策变量”“目标函数”“约束条件”“推导”“算法”“结果分析”等使用无编号加粗引导词，不单独生成编号标题。独立的灵敏度或稳健性分析仅在有独立扰动数据、评价指标或稳定性证据时设置；否则并入结果分析。模型总结框的字段、题型适配和 H5→H6→H8 绑定见 [`../references/model_summary_protocol.md`](../references/model_summary_protocol.md)。

机理反演类还需两条独立求解路线交叉印证；预测、评价、动力学题分别遵循 profile 的基线/权重敏感性/步长稳定性要求，不将某一题型的“两路线”强制套用于全部题目。

## 4. 章节边界

模型选型、约束设计、算法流程、主要求解结果不得整体迁移到检验章或附录。检验章只允许保留扰动、残差、交叉验证、敏感性和鲁棒性证据。

## 5. 结果落地

每个子问题完成推导后在“模型建立”小节末尾集中呈现最终求解模型，完成求解后在“模型求解与结果分析”小节给出主要结果和意义解释。主模型图、拟合图和原始求解结果优先放在模型章节，验证图才放在检验章节。所有数值必须能回溯到结果文件或登记的数据源。

## 6. 严格执行语义

`FULL_CONTEST --strict` 必须自动启用 `check_modeling_contract.py --contract-strict`。严格检查不仅判断章节标题是否出现，还要在每个 6.x 子问题范围内分别找到 profile 要求的假设、推导、算法、结果和可靠性证据；缺失任一项即 BLOCK，不得用整章其他小节的关键词抵扣。

## 7. 结构化证据与推导登记

每个子问题必须提供 `model_contract.yaml` 中的一条证据卡。证据卡至少登记问题映射、假设、符号单位、结果来源和可靠性，并按题型追加机理映射、推导、优化约束、预测基线或评价权重等字段。每个字段必须包含 `status: pass` 和至少一个正文锚点；锚点必须在本子问题的 TeX 范围内真实出现，来源文件必须存在。

正文公式的 `\label{eq:...}` 必须登记在 `derivation_registry.yaml`。定义、外部给定和文献引用公式可登记来源；本文推导公式必须登记前置公式、至少两步推导文字，并在涉及边界或近似时登记假设。缺少登记、步骤或依赖时，严格模式阻断；这不是对数学真值的自动证明，而是把可审计证据交给 Critic 做逐式复核。

执行顺序：

```text
python scripts/init_model_contract.py <project_root>
python scripts/check_model_evidence.py <project_root> --strict
python scripts/check_derivation_chain.py <project_root> --strict
```

草稿生成器不会覆盖既有契约；契约卡不能用 `true` 代替正文锚点，脚本会进行正文交叉核验。

## 7.1 建模—求解前置输入闸门

生成建模求解正文前必须完成 `modeling_solution_contract.yaml` 前置输入闸门：没有赛题小问、假设文件、变量清单和已调试代码逻辑时停止，不凭题目补写模型。每个小问保留 original→rearranged/intermediate→final 推导链、公式含义、三线符号表、算法参数依据和外部结果来源；严格校验命令为 `python scripts/check_modeling_solution_contract.py <project_root> --strict`。

## 8. 模型蓝图影子编译

混合题可在写作前提供 `model_blueprint.yaml`：项目层声明 `composition: hybrid`，每个子问题声明一个或多个
模型节点及 `composition_mode`，跨问题传递量放入 `interface_contract.yaml`。影子编译器只生成结构报告并默认 WARN，
用于校准题型组合、符号和接口规则；未通过真实 replay 前，不得把影子 WARN 当作正式交付 BLOCK。
