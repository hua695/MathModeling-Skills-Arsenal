# 数学建模论文硬性要求

竞赛官方规则和项目 profile 优先。以下规则是国内数模常规默认；只在 profile 启用时执行特定页数、AI 说明或附录编号要求。

## 结构与篇幅

- 标题、摘要与关键词、正文、参考文献、附录顺序清晰；不写目录，除非官方模板要求。
- 国赛 2026 电子版按湖南赛区确认口径计数：摘要不计入正文页数，正文从正文主体起计，包含正文主体、参考文献前的 AI 工具使用声明和参考文献，最多 30 页；提交论文文件总页数不超过 51 页。PDF 必须是含文本层的非图片 PDF，文件不超过 20 MB。
- 一级标题按项目模板组织，通常包括问题重述、问题分析、模型假设、符号说明、模型建立与求解、模型检验与灵敏度分析、模型评价与推广。
- 标题必须自拟，不使用赛题名称、竞赛名称、题号或参赛队信息代替标题。
- 不设置全局正文或附录最低页数；官方规则或项目 profile 明确启用时，按其页数门禁执行。启用国赛个人篇幅 profile 时，正文规划为 25–30 页并先做真实证据容量检查，不能靠扩写或空白凑页。
- 国赛 profile 启用时，LaTeX 源文件上下左右页边距均不小于 2.5 cm。

## 摘要与关键词

- 摘要包含背景、方法、各问结论和独立总评；总评是摘要最后一个非空段。
- profile 启用时摘要为 550–800 字，并按背景、方法、逐问结论、总评分段。
- 关键词通常为 4–6 个，独立成行，位置、加粗和间距按官方模板。
- 摘要中的每个数字、比较和结论都必须能回溯到结果文件或可复算关系。

## 模型、公式与结果

- 每个小问形成“题目映射 → 假设 → 符号 → 原始关系 → 中间推导 → 目标/状态/约束 → 算法参数 → 结果 → 校验”的闭环。
- 新符号首次出现时定义含义、单位/量纲、取值域和变量类型；总符号表不能替代首用定义。
- 公式登记 `original → intermediate/rearranged → final` 链，并说明每步变形依据。
- 结果只来自可复现代码、推导或登记的原始数据；正文、图表、附录和代码中的数字必须一致。
- 模型选择必须说明数据、约束、解释性和计算条件；验证至少覆盖误差、稳健性、灵敏度或适用边界中的适用项。
- 确定要做哪些验证后，具体方法、指标和分级要求由 `data-science-stack` 承接（`validation_methods.md` 已迁入其 references），不改变本节验证范围。

## 图表与排版

- 每张图表有编号、题注、来源、生成脚本、单位、正文引用和结果解读；数量按论证需要决定，不为凑数添加。
- 数据结果图使用 `ModelViz → scipilot-figure-skill`；问题分析流程图和技术路线图使用 `tech-route-maker`；原理、机制、受力和几何示意图使用 `tikz-scientific-figures`；Draw.io 仅在用户明确要求时使用。登记规则以 `references/figure_policy.md` 为准。
- 图表默认居中；表题在表上方，图题在图下方；表格使用三线表，无竖线和无关内横线。
- 无特殊要求时，中文正文宋体小四，数字与英文 Times New Roman，代码 Consolas；标题按官方模板；代码块保持统一字号、行距和 4 空格缩进。
- 正文、标题、表格、图注、参考文献和超链接默认黑色；代码语法高亮仅限代码块。
- 只在官方规则或项目 profile 要求时插入分页符；不得用空白、重复图表或无效段落制造篇幅。

## 附录与 AI 工具说明

- 附录按 `appendix_plan.yaml` 和官方 profile 组织，只纳入真实存在且支撑正文的核心代码、长推导、数据验证、补充表格和必要说明。
- 程序题按小问提供核心代码片段，并在 `core_source_files` 中登记；完整源码通过
  `full_source_files`、`support_source_files` 放入支撑材料包。`appendix_code_mode: full_source`
  仅在项目明确要求时将完整源码嵌入论文附录。
- 随机仿真或随机算法登记真实 seed、依赖和执行顺序；纯解析题不强制添加无关代码。
- 官方 profile 要求 A–E 时，默认顺序为：A 支撑材料清单、B 核心代码、C 推导/演算、D 补充表格/验证、E AI 工具使用说明；官方规则可覆盖编号和顺序。
- 国赛 2026 在参考文献前放置 AI 工具使用声明；使用 AI 时在支撑材料中提供 `AI工具使用详情.pdf`。不要求将 AI 工具列入参考文献；声明与详情须真实覆盖实际使用范围，并说明工具版本、用途环节、关键交互摘要、采纳、人工修改和核验。

## 质量与成品边界

- 写作链执行 `academic-writing` 数模学术写作适配层 → 必要时 `humanizer-zh`，只处理允许的普通正文表达。
- 论文成品不含评审记录、内部讨论、用户或 agent 交流、提示词、交接、修改轮次、调试、失败尝试、旧内容和元话语。
- 文本层、结构、模型、数据、结果、引用、图表、摘要、附录、匿名和交付漂移检查全部通过后，才能进入正式交付。
- 图表默认执行渲染、截图和自动视觉质检；论文、建模、求解、文献、评审及文档等非图表流程默认关闭，用户明确要求时才执行，且不能替代其他门禁。

## 章节内容质量红线

- 摘要逐问给具体数值结论，不只罗列方法名，每个数字都能回溯到结果文件。
- 假设章列出的每条假设必须在后文被使用或验证，列而不用的假设删除。
- 每张图表之后必须有比较或因果解读，说明趋势意味着什么，不能只复述图中数字。
- 模型评价针对本题模型的假设、数据和适用边界，不写所用通用算法的教科书式优缺点。
- 公式针对本题变量与约束从问题推导，不直接套用教科书通用式后代入，公式间变形写出依据。
- 结果分析回答结论含义，描述变化后接模型选择或决策上的解释；无证据的褒义词不替代结果。
- 交付前内容层自审顺序由 `academic-writing` 承接（`paper_self_review.md` 已迁入），主张证据判定参考 `references/paper_claim_review.md`，表达去痕由 `academic-writing` 承接（`de-ai-writing.md` 已迁入），这些是写作参考，不新增机器门禁。
