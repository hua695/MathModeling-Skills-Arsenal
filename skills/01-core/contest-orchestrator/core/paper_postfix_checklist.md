# 论文生成后检查清单

写作阶段按预防项执行；DOCX、PDF 或 LaTeX 生成后逐项检查。发现问题时修复源文件或生成脚本，再重新生成成品。

## A. 代码块

| 编号 | 检查项 | 预防措施 |
|---|---|---|
| A1 | 代码使用 `minted` 或项目批准的等宽代码环境 | 导言区配置代码包，附录引用外部源文件 |
| A2 | 特殊字符、缩进和行号可编译 | 使用受支持的代码环境并检查长行 |
| A3 | 代码环境与依赖版本可复现 | README 登记语言、版本、依赖和执行顺序 |
| A4 | 核心代码按题号和功能拆分 | 文件清单与附录清单一一对应 |

## B. 附录

| 编号 | 检查项 |
|---|---|
| B1 | 附录按项目计划组织：材料清单、核心代码、推导、数据验证、AI 工具说明 |
| B2 | 每题核心代码、推导和数据材料均有真实来源 |
| B3 | 附录文件名、引用路径和正文说明一致 |
| B4 | 随机算法登记 seed；完整源码放支撑材料，正文只保留必要实现 |

## C. 图表与引用

| 编号 | 检查项 |
|---|---|
| C1 | 图题存在，图号连续，正文引用与登记表一致 |
| C2 | 图、表、正文使用同一结果源，数字可回溯 |
| C3 | 引用达到竞赛 profile 要求，格式统一，正文引用无孤立条目 |
| C4 | 灵敏度、分布、模型评价和改进内容按大纲完整呈现 |

## D. 生成与交付

| 编号 | 检查项 |
|---|---|
| D1 | PDF 可打开、文本层完整、尾部结构正常 |
| D2 | DOCX 公式为可编辑 OMML，图已嵌入且无乱码 |
| D3 | 生成命令、依赖和门禁脚本可运行 |
| D4 | 正式 PDF 与当前源文件、交付清单和索引哈希一致 |

## E. 源文件版面与引用

| 编号 | 检查项 | 检查入口 |
|---|---|---|
| E1 | 不使用不必要的固定浮动、连续分页或手工留白 | `check_tex_layout_patterns.py` |
| E2 | 每个 `ref`、`eqref`、`cref` 对应唯一真实 `label` | `check_tex_references.py` |
| E3 | 页数由真实模型内容支撑，不用空白页或重复内容填充 | `check_paper_hard_requirements.py` |
| E4 | 正式交付目录无 PDF 或索引漂移 | `check_formal_delivery_drift.py` |

## 执行规则

源文件修复后必须重新编译，并重新运行与变更相关的模型、数字、引用、图表、版面和交付门禁。任何门禁未通过都不能交付成品。
