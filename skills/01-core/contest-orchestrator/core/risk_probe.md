# 风险探针（Risk Probe · 五维）

> 定位：**baseline-gate 的前置动作**——在运行最简基线前检查主方法是否存在致命风险。
> 目的：大多数翻车发生在"方法选完才发现跑不动/结果退化/数据不够"，此时已来不及换。探针在**完整实现前**暴露这类问题。

## 执行时机与位置

```
literature → 架构候选池 → 【风险探针（本模块）】→ baseline-gate → 建模求解
                              ↑
        注入时机：solving 最早期，baseline-gate 判定前（execution.md 生成顺序铁律）
```

主方法必须过探针；不通过且有缓解方案 → 先缓解再进 baseline；无缓解 → 换备用方法（来自文献候选池，不是现场发明）。

## 五维探针

对每个子问题的主方法，逐维输出：**PASS / WARN / RISK + 一句话依据 + 缓解方案**。

### 1. 数据覆盖（Data Coverage）
**问**：方法需要的每个输入，有没有数据？质量够吗？
- 列缺失率 >20% 的关键输入？→ 插值/剔除后是否影响方法成立
- 样本量 vs 方法需求（小样本硬上深度学习/XGBoost 大调参 = 过拟合）
- 类别不平衡？时间跨度覆盖完整周期（季节/峰值）？
- 无数据处用了什么替代（插值/假设），替代是否改变问题性质
> 可自动化：对数据文件跑缺失率/样本量/类别频数统计（配合 data-science-stack 的 EDA 报告）。

### 2. 关键假设（Assumption Risk）
**问**：模型依赖的假设在本题是否成立？
- 线性/平稳/独立/正态/无后效——逐条对照题面事实
- 假设不成立时模型是否仍可用（鲁棒区间有多大）？
- 每条假设都要有"为什么合理"的一句话（论文也要写，这里先自查）
> 与 problem-parser 的 Assumptions 输出对账：假设表里每一条都要过"成立性"审查。

### 3. 输出集中度（Output Degeneracy）
**问**：模型输出会不会退化？——全是常数、全同解、平凡解、不随输入变化。
- 目标函数有无退化面（例如最优解不唯一且都平庸）
- 初值/随机种子不同 → 结果是否剧变（多跑 3 个种子对比）
- 分类任务：是否永远预测多数类？回归：是否收敛到均值？
> 发现退化 = 方法不可用，直接换备用，不要"先跑跑看"。

### 4. 扰动敏感（Perturbation Sensitivity）
**问**：输入微扰 → 输出大变？（病态问题，结果不可信）
- 按题型 profile 与项目 `sensitivity_plan.yaml` 声明关键参数、扰动范围、场景数、重复次数和判定依据；不使用全局固定比例或固定组数
- 数据噪声水平下结果是否稳定（这决定灵敏度分析能不能写）
> 与灵敏度分析的区别：探针只看"是否病态"，灵敏度分析是正式交付物。

### 5. 规模可行性（Scale Feasibility）
**问**：问题规模在求解预算内吗？
- 决策变量/约束规模 vs 求解器能力（pyomo 精确 vs 启发式切换线）
- 估算单次求解耗时 × 需要跑的次数（灵敏度/调参/多轮）≤ 剩余时间
- 32 核并行能摊平多少（依赖关系是否串行瓶颈）
> 估算公式：`单次耗时 × 运行次数 ≤ 剩余预算 × 0.7`（留缓冲）。

## 输出格式（探针摘要，进 decision_trace）

```markdown
## 风险探针摘要 · 问题Q1 · 主方法=XX
| 维度 | 结论 | 依据 | 缓解/处置 |
|---|---|---|---|
| 数据覆盖 | PASS | 关键列缺失率<5%，n=800 | - |
| 关键假设 | WARN | 线性假设在极端区间不成立 | 分段线性/加二次项 |
| 输出集中度 | PASS | 3 种子结果一致 | - |
| 扰动敏感 | PASS | 已按项目计划完成并报告波动、残差/误差或稳定性证据 | 项目声明的判定依据 |
| 规模可行性 | RISK | 求解 4h/次 × 20 次超预算 | 换启发式 or 降网格 |
→ 结论：通过（WARN 已缓解）／不通过，换备用=XX
```

## 与现有机制的关系

- **baseline-gate**（execution.md）：gate 判"最简基线能否解出合理结果"；探针判"主方法本身有没有致命伤"——探针在前，gate 在后，两层过滤。
- **风险登记表**（planning.md risk-register）：探针结论并入 risk-register 逐条追踪。
- **文献候选池**（planner）：备用方法必须来自文献池，探针不通过时直接切换，禁止现场发明新方法。
- **decision_trace**：探针摘要落盘，赛后 Replay 复用（"这个题型的主方法有哪些致命伤"是宝贵的经验条目）。
